BuildWhat gets compiled

make runs _makedirs_ external_srcs appdir gateware s3gw_drivers. external_srcs expands to Startup, HAL, FreeRTOS, Libraries and BSP, and Libraries runs Power, SysFlash, Utils, FPGA and CLI. Each sub-makefile wildcards *.c in its directory, drops the listed files, and compiles into the shared output/ folder.

Present in GCC_Project/makefiles/ but never invoked: Audio, Chandalar_BOARD, DatablockManager, DatablockProcessor, FrameworkLib, FreeRTOS_FAT (+Common, +QL), Hybrid, M4, QLUART, SensorFramework, Test, appfpga, qlfs, riff_file.

NotesThings the trace turned up

Mismatch

Header misspells qomu_hardwaresetup

BSP/qomu/inc/qomu_hardwaresetup.h:24 declares qomu_hardwareSetup (capital S), which is defined nowhere. That's why main.c:60 carries its own extern void qomu_hardwaresetup();.

Mismatch

axFPGABitStream_length type

main.c:47 declares it extern int; app/fpga/qomu_fpga.c:1906 defines it as uint32_t. The linker can't see the difference and it works on Cortex-M4, but it's undefined behavior by the standard.

Inversion

FreeRTOS tick lives in the Power library

port.c:682 defines vPortSetupTimerInterrupt as weak; the strong copy in Libraries/Power/src/s3x_lpm.c:171 replaces it at link time. Meanwhile Power calls xTaskGetSchedulerState back in the kernel.

Inversion

BSP depends on app files

qomu_hardwaresetup() calls S3x_pwrcfg_init() from app/src/s3x_pwrcfg.c and reads pincfg_table from app/src/pincfg_table.c. Any app using this BSP must provide both.

Routing

dbg_str goes to USB serial, not the UART

Fw_global_config.h:92 sets DEBUG_UART to UART_ID_USBSERIAL, so dbg_ch_raw → uart_tx_raw → HAL_usbserial_putc. The hardware UART that uart_setup() configures isn't used for these prints, which is why they come after HAL_usbserial_init2.

Build hygiene

The link globs output/*.o

Change a filter in a sub-makefile and the old object stays in output/ and keeps getting linked until you make clean.

Leftover

Copied identity string

SOFTWARE_VERSION_STR is set to "qorc-sdk/qf_apps/qf_helloworldsw", the QuickFeather app this one was cloned from.

Unused

Includes main.c doesn't use directly

eoss3_hal_gpio.h, eoss3_hal_rtc.h, ql_time.h, s3x_clock.h, s3x_pi.h, semphr.h, timers.h, RtosTask.h, <stdio.h>. Nothing in main.c names anything from them.

Not a clash

A second main() in Utils

Libraries/Utils/src/ql_test_signals.c:272 has a main(), but it sits under #ifdef TST_QL_MATHOPS, which isn't defined. Tag-based tools will still show two.

Method: static trace from source (ctags plus a scan of each function body for calls to other compiled functions), using the exact file set the makefiles select. There was no output/ folder or ARM toolchain to check against a real .map file. Calls through function pointers (CLI menu handlers, ISRs, task entry points) don't show up as edges, and code inside inactive #if branches may appear in the tree.
